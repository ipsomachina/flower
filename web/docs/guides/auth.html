Authentication and authorization

The server does not know your users. Each module decides who a caller is with an authorization component, each method declares who may call it, and collections can protect rows and fields with declarative access policies the engine enforces on every read and write.

How a call is authorized

  1. The server resolves the name. Only methods declared http answer; any other name answers 404 UNKNOWN_METHOD, whether or not the module defines it.
  2. The server turns the request's credentials into a JSON value: the body's credentials member if present, otherwise {"bearer": "<token>"} from an Authorization: Bearer header — unless the token is one of the server's own tokens, which are never shown to guest code — otherwise null. Watches are requests like the others: the same body, the same header.
  3. If the module lists an Authorization component, its hook runs on the call's own snapshot. It authenticates the caller into a principal and checks the method's access, or refuses. A refusal answers 403 with code unauthorized and a message starting with the hook's own code: UNAUTHENTICATED: authentication required, FORBIDDEN: access denied.
  4. The method runs. It reads the principal with ctx.principal(), and every collection operation it performs is checked against that collection's access policy.

A module without a hook runs every call anonymously. Calls without an external caller — timer firings, triggers, maintenance tasks, derived evaluations — skip the hook and run with the module's own rights.

Bearer JWTs with JwtBearer

The usual setup verifies JSON Web Tokens from an identity provider. JwtBearer is a ready-made typed authenticator:

/// An ES256 public key from your identity provider, as PEM.
const IDP_PUBLIC_KEY: &str = "-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----\n";

static BEARER: JwtBearer = JwtBearer {
    issuer: Some("https://auth.example.com/"),
    audience: &["notes-api"],
    clock_tolerance_seconds: 30.0,
    ..JwtBearer::new(BearerKey::Pem(IDP_PUBLIC_KEY, &[Algorithm::Es256]))
};

/// List it among the app's components, at most one per module.
pub static AUTHORIZATION: Authorization = Authorization {
    authenticate: Authentication::Typed(&BEARER),
    // Methods that declare no `access` need a signed-in caller...
    default: Access::Authenticated,
    // ...as do retry sessions.
    sessions: Access::Authenticated,
    // Access for what other macros declare (`external!` operations,
    // interface providers), by name.
    methods: &[],
};

/// A method declares its own access where it differs from the default.
#[query(http, access = public)]
pub fn health(ctx: &mut QueryCtx<'_, '_>) -> String {
    let _ = ctx;
    String::from("ok")
}
  • Keys. BearerKey::Pem(pem, &[algorithms]) takes a PEM public key; BearerKey::Bytes(bytes, KeyFormat::Raw | Der, &[algorithms]) an HS256 secret or a DER public key; BearerKey::Managed(&KEY) a managed key from the cluster's catalog (for tokens your own module issued with that key). Algorithms are Hs256, Rs256, Es256 and EdDsa. There is no JWKS fetching: guests have no network, so embed the provider's keys or store them in a collection and use a callback hook.
  • Claims. exp is required. issuer makes iss required and exact. The audience check is strict both ways: with an audience list, the token's aud must contain one of them; without one, a token that carries aud is refused. Only the alg, typ and kid protected headers are accepted.
  • Principal. By default (claims_principal), sub becomes the subject, a string tenant claim the tenant, and all claims the principal's claims. Set principal to your own fn(&Value) -> Result<Option<Principal>> to map claims differently.
  • Credential shapes. It accepts the bearer header, {"bearer": t}, {"token": t} or a bare string; null is anonymous; anything else is UNAUTHENTICATED.

Verification runs in the server's crypto host, which every server has: a PEM or raw key needs no setup. Only BearerKey::Managed needs the database's key catalog provisioned.

Method access

The Authorization component says how callers authenticate and what access applies where a method declares none:

FieldMeaning
authenticateAuthentication::Typed(&authenticator), Callback(fn), Gateway (trust the principal a gateway holding the admin token asserts) or Anonymous.
defaultAccess for every method that declares none.
sessionsAccess for opening, reading, acknowledging and closing retry sessions.
methodsAccess for definitions declared where no access option reaches, by name: an external! value's operations, an interface provider's methods. Usually empty.

A method states its own access in its declaration, where it differs from the default: #[query(access = public)], access = authenticated, or access = path::to::check for a predicate. Raw descriptors take .access(Access::..), and so do transactions (Transaction::new(..).access(..)). The manifest refuses a methods entry naming a definition the app does not have, one named twice, or one whose definition declares its own access — a typo cannot silently leave a method on the default — and it refuses any declared access in a module without an authorization component.

Access::Public lets anyone in, Access::Authenticated requires a principal (UNAUTHENTICATED otherwise), and Access::Check(fn) runs your predicate over the principal and the call's arguments (FORBIDDEN when it returns false). Authentication runs first, so invalid credentials are refused even for public methods; only no credentials make an anonymous caller. A module lists at most one Authorization among its components:

pub static APP: App = App::new(&[
    &AUTHORIZATION,
    &Notes,
    &HEALTH,
    &WHOAMI,
    &NOTE,
    &RETITLE,
    &FORGET_PRIVATE,
]);

Methods read the principal through MethodCtx:

#[derive(FlowerType, Clone, Debug, PartialEq)]
pub struct Me {
    pub subject: Option<String>,
    pub tenant: Option<String>,
}

#[query(http, access = authenticated)]
pub fn whoami(ctx: &mut QueryCtx<'_, '_>) -> Result<Me> {
    let principal = ctx.principal()?;
    Ok(Me {
        subject: principal.as_ref().map(|p| p.subject.clone()),
        tenant: principal.and_then(|p| p.tenant),
    })
}

Custom hooks

When credentials are not JWTs — opaque session tokens, API keys, signed requests — write the hook yourself. It is a query: it can read collections (with the module's own rights), read the clock and use guest crypto, but it cannot write. Here opaque session tokens are looked up in a sessions collection, and methods are open only to callers of the tenant they name:

/// Opaque session tokens: the session row decides who the caller is,
/// until the session expires or the row changes.
fn by_session(
    ctx: &mut QueryCtx<'_, '_>,
    credentials: &Value,
    _request: &AuthRequest,
) -> Result<Option<Principal>> {
    let token = match credentials {
        Value::Null => return Ok(None),
        Value::Object(fields) => match fields.get("bearer") {
            Some(Value::String(token)) => token.clone(),
            _ => return Err(fail("UNAUTHENTICATED", "expected a bearer token")),
        },
        _ => return Err(fail("UNAUTHENTICATED", "expected a bearer token")),
    };
    let Some(session) = Sessions::get(ctx, &token)? else {
        return Err(fail("UNAUTHENTICATED", "unknown session"));
    };
    // `clock`, not `now`: the decision can then be kept until expiry.
    if ctx.clock()? >= session.expires_at {
        return Err(fail("UNAUTHENTICATED", "session expired"));
    }
    ctx.changes_at(Some(session.expires_at))?;
    Principal::new(session.user, Some(session.tenant), None).map(Some)
}

/// Only callers of the tenant the arguments name.
fn same_tenant(
    _ctx: &mut QueryCtx<'_, '_>,
    principal: Option<&Principal>,
    args: &Value,
) -> Result<bool> {
    let named = match args {
        Value::Object(fields) => fields.get("tenant"),
        _ => None,
    };
    Ok(match (principal.and_then(|p| p.tenant.as_deref()), named) {
        (Some(mine), Some(Value::String(named))) => mine == named,
        _ => false,
    })
}

/// Every method checks the tenant unless it declares otherwise, as
/// `whoami` does.
pub static SESSION_AUTHORIZATION: Authorization = Authorization {
    authenticate: Authentication::Callback(by_session),
    default: Access::Check(same_tenant),
    sessions: Access::Authenticated,
    methods: &[],
};

Over HTTP, a missing or unknown token, or a caller of another tenant, is refused before the method runs:

{"code":"unauthorized","message":"UNAUTHENTICATED: authentication required","ok":false}   // 403, no token
{"code":"unauthorized","message":"UNAUTHENTICATED: unknown session","ok":false}         // 403, bad token
{"ok":true,"value":{"subject":"ada","tenant":"acme"}}                                    // whoami as ada
{"code":"unauthorized","message":"FORBIDDEN: access denied","ok":false}                 // 403, tenant "globex"

State-changing checks — consuming a one-time code, counting attempts — belong in a mutation, not the hook: the hook commits nothing.

Tenants and partitions The hook is not told which database it serves. If tenants live in their own databases, bind the tenant to the database through the database's own data (a settings row naming its tenant), or through the arguments, as same_tenant does.

Decision reuse and expiry

Running the hook on every call would be wasteful, so the engine keeps its decisions in a memo (4 MiB by default, --decision-memo-bytes). A kept decision answers a later call with the same credentials while all of these hold:

  • the module's code has not changed;
  • nothing the hook read has changed — deleting the session row ends every decision that read it;
  • the decision has not expired: JwtBearer declares the token's exp (plus tolerance), and a callback hook declares with ctx.changes_at. The earliest declaration wins, so a session expiring in an hour cannot extend a token expiring in a minute;
  • for a hook that reads the arguments (callbacks and Check predicates), the arguments are the same.

Denials are never kept, nor are decisions from a hook that called now(). Read the time with clock() and declare the expiry with changes_at, as by_session does. Retries of recorded writes are authorized again before they are answered, so a revoked caller cannot read a recorded result.

Watches

A watch presents credentials as a query does, in its body or its Authorization header. Every watch delivery is authorized at the revision it shows. The server rechecks each subscriber when something the decision read changes, when the decision expires, when a managed key it used changes, and at least every 30 seconds. A subscriber who is no longer allowed gets an error event with code unauthorized and the stream ends; one whose principal changed (new claims, another tenant) gets watch_scope_changed and should reconnect.

Access policies

Method access decides who may call. Access policies decide which rows and fields each caller may read and write, whatever method they call. A policy is a set of rules over operands — the stored row (row), the row being written (next), the key, the principal (subject, tenant, claim), the time (now) — attached to a collection with its access option, which names a fn() -> Policy:

#[derive(FlowerType, Clone, Debug, PartialEq)]
pub struct Note {
    pub owner: String,
    pub title: String,
    /// Hidden from everyone but the owner: absent when redacted.
    pub private: Field<String>,
}

/// The collection with its access policy.
#[collection(
    name = "notes",
    key = String,
    value = Note,
    index(name = "by_owner", fields(owner), types(String)),
    access = notes_policy,
)]
pub struct Notes;

fn notes_policy() -> Policy {
    let mine = Operand::row(&["owner"]).eq(Operand::subject());
    let admin = Operand::claim(&["role"]).eq(Operand::literal("admin"));
    Policy::new()
        .read(Rule::authenticated())
        .insert(Operand::next(&["owner"]).eq(Operand::subject()))
        .update(
            mine.clone()
                .and(Operand::next(&["owner"]).eq(Operand::row(&["owner"]))),
        )
        .delete(mine.clone().or(admin))
        .field("private", FieldAccess::new().read(mine))
}

A raw Collection takes the same function with .access(notes_policy).

RuleChecked onSees
readgets, scans, index ranges, historythe stored row, key, principal, time
insertwriting a new keythe written row (next)
updatereplacing an existing rowboth row and next
deletedeletingthe stored row
writeshorthand for insert, update and delete
field(name, FieldAccess)reading and changing one top-level fieldread: the stored row; write: both
  • Deny by default. Policy::new() denies everything; an operation without a rule is refused. A collection without a policy is open.
  • Missing is never equal. A comparison with a missing or null side is false, so an anonymous caller never matches row.owner == subject.
  • Lookups. Rule::stored(collection, key) requires a row to exist in another collection of the module (a membership table, say); Rule::readable(collection, key) also requires the caller to be allowed to read it.
  • Derived values take a single rule over the principal and arguments: Derived::new(…).access(fn() -> Rule). Derived values compute with the module's own rights and can see guarded rows — expose them deliberately.
  • Cost. A policy is folded once per call and collection; rules that depend only on the caller cost nothing per row. When the read rule is row.f == subject and an index covers exactly f, scans read only that index bucket — so index the owner field.

Hidden rows and redacted fields

A row the caller may not read is invisible: get returns None, and scans and ranges drop it before applying limits and cursors. A visible row loses the fields the caller may not read — the member is absent, not null — and a typed row decodes it as Field::Redacted:

#[derive(FlowerType, Clone, Debug, PartialEq)]
pub struct NoteView {
    pub title: String,
    pub private: Option<String>,
}

#[query(http)]
pub fn note(ctx: &mut QueryCtx<'_, '_>, id: String) -> Result<Option<NoteView>> {
    // Rows the caller may not read come back as `None`; fields it may
    // not read come back as `Field::Redacted`.
    Ok(Notes::get(ctx, &id)?.map(|note| NoteView {
        title: note.title,
        private: match note.private {
            Field::Visible(text) => Some(text),
            Field::Redacted => None,
        },
    }))
}

#[mutation(http)]
pub fn retitle(ctx: &mut MutationCtx<'_, '_>, id: String, title: String) -> Result<()> {
    let Some(note) = Notes::get(ctx, &id)? else {
        return Err(fail("NOT_FOUND", "no such note"));
    };
    // A redacted field cannot be encoded, so write the fields you may
    // see; the engine keeps the stored values of the ones you may not.
    let mut row = alloc::collections::BTreeMap::new();
    row.insert(String::from("owner"), Value::String(note.owner));
    row.insert(String::from("title"), Value::String(title));
    if let Field::Visible(private) = note.private {
        row.insert(String::from("private"), Value::String(private));
    }
    ctx.set(
        CollectionRef::local(Notes::NAME),
        &Value::String(id),
        Value::Object(row),
    )
}

#[mutation(http)]
pub fn forget_private(ctx: &mut MutationCtx<'_, '_>, id: String) -> Result<()> {
    let Some(note) = Notes::get(ctx, &id)? else {
        return Ok(());
    };
    let mut row = alloc::collections::BTreeMap::new();
    row.insert(String::from("owner"), Value::String(note.owner));
    row.insert(String::from("title"), Value::String(note.title));
    // Remove the field outright, even if this caller cannot see it:
    // that takes the field's write rule.
    ctx.set_clearing(
        CollectionRef::local(Notes::NAME),
        &Value::String(id),
        Value::Object(row),
        &["private"],
    )
}
  • Writing back a row with hidden fields keeps their stored values, so a read-modify-write by a caller who cannot see everything loses nothing. A Field::Redacted cannot be encoded (REDACTED_VALUE), so write the visible fields, as retitle does.
  • To remove a field, including one the caller cannot see, use set_clearing: it takes the field's write rule.
  • A refused write fails with ACCESS_DENIED. In a mutation that is the call's own failure — 422 {"ok":false,"revision":2,"position":11,"code":"ACCESS_DENIED","message":"access policy denies this write to `notes`","duplicate":false} over HTTP — which a calling module can recover from with a savepoint.
  • Deleting a row the caller cannot see does nothing, as for a missing key.

Gateways and server tokens

The server has three tokens of its own, configured on cargo flower serve: the admin token (operator endpoints), the worker token (queue endpoints) and the sync token (replica sync). None of them is ever passed to a hook. A request bearing the admin token is a trusted gateway: it may assert the principal a call runs as (body principal: {"subject", "tenant"?, "claims"?}) and the time a mutation commits at (timestamp_ms), in call and watch bodies alike; from anyone else both fields are ignored. A hook decides what to make of an asserted principal — Authentication::Gateway trusts it outright, while JwtBearer still wants a token. Use this for a backend that authenticates users itself and calls Flower on their behalf. A gateway gets no more time than anyone: how long a call may run is the method's own declaration, which a caller can only shorten.
