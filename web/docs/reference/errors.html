Error codes and limits

Every failure carries a stable code. UPPER_SNAKE_CASE codes come from guests and the SDK — yours among them; lowercase codes come from the engine and server. The HTTP status tells a client what to do.

Reading a failure

  • 422 is the call's own answer: a code its code chose, bad arguments, a limit it ran out of, its code trapping, and every failure a mutation or transaction recorded. The body is {"ok":false,"code","message","details"?}, plus revision, position and duplicate for a recorded write. Final: show it, don't retry it.
  • 503 means nothing ran, or the outcome is unknown and another attempt may get through; retry, writes with the same request ID.
  • 400, 404, 413 and 415 refuse the request itself; 403 refuses the caller; 409 refuses an operator change; 500 is any other host failure.
  • The authorization component's refusals are wrapped: code unauthorized, message "<HOOK CODE>: <message>".

The status column below is what a call answers when it fails with that code; "—" marks codes a guest sees from an SDK or host call and handles itself (a call that returns one fails with 422).

Deadlines and budgets

CodeHTTPMeaning
deadline_exceeded422The call ran past its own deadline: its method's timeout, the operator's default, or its transaction's. Declare a longer timeout, or do less per call.
budget_exhausted422The instruction or host-operation budget derived from the call's deadline ran out: the same on every member.
caller_deadline_exceeded503The caller's x-flower-timeout-ms passed first. An attempt with more time may succeed.
out_of_memory422An instance or the invocation hit its memory limit.
stack_overflow422The Wasm stack overflowed.
nesting_too_deep422More than 32 nested calls.

These end the invocation: savepoints cannot catch them.

SQL failures

CodeHTTPMeaning
SQL_INVALID422Invalid syntax, logical binding, plan name, limit or unsupported access path. Parser errors include zero-based UTF-8 start_byte and exclusive end_byte offsets.
SQL_BUDGET422A configured candidate, byte or work ceiling was exhausted. Evaluator failures identify the dimension in details.budget. No partial result is returned.

Parameter contract mismatches use INVALID_ARGUMENT; reading a collection outside an endpoint's scope uses ACCESS_DENIED. SQL failures are separate from the invocation's host-fuel exhaustion. See SQL budgets and limits.

Retries and receipts

Recorded outcomes of a write, answered 422: identity_conflict, epoch_retired, epoch_not_admitted, wrong_history, receipt_released, receipt_budget_exceeded, retry_session_unknown, retry_session_mismatch, retry_session_closed, retry_session_forbidden, retention_not_initialized, already_acknowledged, retry_ack_gap, retry_ack_budget, retention_epoch_moved. See Retries and receipts.
