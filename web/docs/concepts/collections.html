Concepts

Collections and indexes

Source records live in collections: typed rows under unique keys. The engine validates every write against the collection's schemas and maintains its indexes and references in the same commit.

Values and typed contracts

Everything that crosses the guest boundary — arguments, results, stored rows, keys — is a JSON-compatible Value: null, booleans, finite numbers, strings, arrays and objects with unique keys, at most 128 levels deep. In Rust you rarely touch Value directly. Instead you derive FlowerType, which gives a type a schema (used for validation and for module contracts), an encoder and a decoder:

/// A project. Wire names are the Rust field names.
#[derive(FlowerType, Clone, Debug, PartialEq)]
pub struct Project {
    pub name: String,
}

/// A unit enum is a closed string enum: `"low"`, `"normal"` or `"high"`.
#[derive(FlowerType, Clone, Copy, Debug, PartialEq)]
pub enum Priority {
    Low,
    Normal,
    High,
}

#[derive(FlowerType, Clone, Debug, PartialEq)]
pub struct Task {
    pub project: String,
    pub owner: String,
    pub title: String,
    pub priority: Priority,
    /// Due time, epoch milliseconds.
    pub due: u64,
    /// `null` is a visible value: the member must be present.
    pub notes: Option<String>,
    /// Absent members decode as `Vec::new()`.
    #[flower(default)]
    pub tags: Vec<String>,
}

The rules the derive follows:

  • Wire names are field names, or their camelCase forms when the struct says #[flower(rename_all = "camelCase")], for clients speaking JavaScript conventions. A raw identifier is plain on the wire (r#type is type), and two fields answering to one wire name are a compile error. There is no per-field rename and no flatten. Named structs decode as closed objects: an unknown member is rejected with INVALID_VALUE.
  • Option<T> is a visible null. In a struct the member must be present; its value may be null. (A method's Option parameter, by contrast, is a member callers may leave out.) To make a member optional, add #[flower(default)] (absent decodes as Default::default()) or #[flower(default = path)].
  • #[flower(skip)] leaves a field out of the schema and the encoding and fills it with Default when decoding.
  • Unit enums are closed string enums named after the variants. Single-payload enums encode as {"tag": "Variant", "value": …}. Tuple structs, unions, mixed enums and multi-field variants are refused.
  • Integers are exact. i64 and u64 accept only the safe-integer range, ±(253 − 1); wider values fail rather than round. Use typed::DecimalI64 / DecimalU64 for the full range, carried as decimal strings.
  • Built-in types include (), bool, String, finite f64, the integer types, Option, Vec, Box, tuples of one to four elements, and Value itself for deliberately untyped data.

Codec failures have stable codes: TYPE_MISMATCH (wrong JSON kind), MISSING_FIELD, INVALID_VALUE (right kind, wrong content) and SCHEMA_MISMATCH (rejected by a schema). A method's arguments are checked before your code runs, and a refusal there is INVALID_ARGUMENT, with details.path naming the offending member (["items", 1, "count"]). See Error codes.

Declaring a collection

The #[collection] attribute declares a collection on a marker struct, with its key type, row type, indexes and references. The marker is both the typed handle and the component the app lists:

#[collection(name = "projects", key = String, value = Project)]
pub struct Projects;

#[collection(
    name = "tasks",
    key = String,
    value = Task,
    index(name = "by_owner_due", fields(owner, due), types(String, u64)),
    // A field reference needs an index whose fields start with its own.
    index(name = "by_project", fields(project), types(String)),
    reference(target = Projects, fields(project), on_delete = cascade),
)]
pub struct Tasks;

For each marker the macro generates:

ItemWhat it is
Tasks::NAMEThe collection name, "tasks".
Tasks::get(ctx, &id)Read one row by key, decoded: Result<Option<Task>>. Works in any context.
Tasks::set(ctx, &id, &task)Encode and upsert. Mutations only.
Tasks::delete(ctx, &id)Delete one row. Mutations only.
Tasks::page(ctx, limit, after)One page of the whole collection in host order.
Tasks::SOURCEA typed Source<K, V> read handle: get, page, and in_module to read another module's exported collection of the same shape.
Tasks::BY_OWNER_DUEA typed Index handle, one per index whose name is a valid identifier.
Tasks::raw()The raw Collection descriptor, for code that works on descriptors.

Register the collection by listing the marker among the app's components: App::new(&[&Tasks, ...]). A collection you do not register does not exist. Two more options go in the attribute: export lets the database's other modules read the collection (see exports), and access = policy guards callers' operations on it with an access policy.

Keys

A key is a value of the collection's key type: a String, a number, or a tuple for a compound key. The handles take it as it is:

#[mutation]
pub fn rename_task(ctx: &mut MutationCtx<'_, '_>, id: String, title: String) -> Result<bool> {
    let Some(mut task) = Tasks::get(ctx, &id)? else {
        return Ok(false);
    };
    task.title = title;
    Tasks::set(ctx, &id, &task)?;
    Ok(true)
}

On the wire and in storage a key is its canonical JSON rendering — the string key milk is "milk", the tuple key ("acme", 7) is ["acme",7] — so every key has exactly one form, and keys of every type order consistently in scans. The SDK renders keys for you; the raw context operations take keys as Values (anything FlowerType encodes to one) and render them the same way.

Scan and range results hand keys back as decoded values (row.key is a String above), so you never parse key text.

Host order Pages come back in the host's storage order: shorter key text first, then by bytes. It is not the order of your Rust type and not lexicographic order — "milk" sorts before "bread". Never synthesize cursors; continue from the one the host returned.

Indexes and range queries

An index names one or more fields of the row; the engine maintains its entries atomically with every write. types(...) gives the typed handle the fields' Rust types, so prefixes and bounds are type-checked; without it the components are Values.

A range fixes a prefix of the indexed fields, then optionally bounds the next field from below (gt/gte) and above (lt/lte), and returns a page of at most limit rows with a continuation cursor:

#[derive(FlowerType, Clone, Debug, PartialEq)]
pub struct DuePage {
    pub titles: Vec<String>,
    /// Pass back as `after` for the next page; `null` after the last.
    pub next: Option<String>,
}

#[query]
pub fn due_between(
    ctx: &mut QueryCtx<'_, '_>,
    owner: String,
    since: u64,
    until: u64,
    after: Option<String>,
) -> Result<DuePage> {
    let mut range = Tasks::BY_OWNER_DUE.prefix((owner,)).gte(&since).lt(&until);
    if let Some(cursor) = &after {
        range = range.after(cursor);
    }
    let page = range.page(ctx, 50)?;
    Ok(DuePage {
        titles: page.rows.into_iter().map(|row| row.value.title).collect(),
        next: page.cursor,
    })
}
  • prefix(()) — or Tasks::BY_OWNER_DUE.query() — ranges over the whole index; a prefix covering every field takes no bounds and returns the rows equal to it.
  • .reverse() walks the range descending; .after(cursor) continues a previous page. The host checks that a cursor belongs to the range it continues (INVALID_VALUE, "out of scope", otherwise).
  • Bounds compare in the index's stored component order, which for numbers follows the canonical text — another reason to keep numeric index fields within the same magnitude, or to use fixed-width encodings.
  • DecimalI64 and DecimalU64 values order as strings in an index, not as numbers.

To walk a whole collection, page it until the cursor runs out:

#[query]
pub fn project_names(ctx: &mut QueryCtx<'_, '_>) -> Result<Vec<String>> {
    let mut names = Vec::new();
    let mut after: Option<String> = None;
    loop {
        let page = Projects::page(ctx, 100, after.as_deref())?;
        names.extend(page.rows.into_iter().map(|row| row.value.name));
        match page.cursor {
            Some(cursor) => after = Some(cursor),
            None => return Ok(names),
        }
    }
}

Pagination is live Each page is a separate read. Across calls, records changed between pages can be skipped or repeated. Within a single invocation, every page reads the same snapshot.

References

A reference declares a foreign key from this collection to another. The engine checks it on every write and acts on it when the target row is deleted:

on_deleteDeleting a referenced row…
restrict (default)fails while any row still refers to it.
cascadedeletes the referring rows too, in the same commit.
set_nullsets the referring fields to null.

The reference can sit in named fields (fields(project)), in the whole key (key) or in a key prefix (key_prefix). A field reference can be polymorphic: targets(Posts, Comments) with a discriminator field naming which collection each row points to. Targets name the marker structs of collections in scope. Cascading deletes and triggers abort with cascade_too_deep beyond 16 rounds.

A field reference needs an index the engine can use to find the rows that refer to a target: one whose fields start with the reference's fields, as by_project above does for fields(project). A polymorphic one needs an index over the discriminator followed by the reference's fields. Without one, #[collection] refuses the reference at compile time and names the index to add; a hand-built Collection descriptor is refused at deployment ("field reference without a covering index").

Writes in detail

Inside a mutation, reads see the mutation's own staged writes. Nothing is visible to anyone else until the mutation returns successfully and the engine commits. Besides set and delete, the mutation context offers:

  • delete_if_match(collection, &key, &expected) — delete only when the stored row equals expected; returns whether it did.
  • delete_permanently(collection, &key) — delete without running retention hooks, for the row and the deletes it cascades into.
  • set_clearing(collection, &key, value, &["field"]) — upsert and remove named fields. A caller whose access policy hides fields from it otherwise keeps their stored values when it writes the row back.

These are raw operations: collection is a CollectionRef (CollectionRef::local(Tasks::NAME)), and keys and rows are Values (&Value::String(id), or id.encode()?). Every stored row must validate against the collection's value schema; a typed row can never be null, and a missing row reads as None.

Raw, untyped collections

The typed layer sits on a raw one you can use directly for deliberately dynamic code. Collection::new("orders").indexes(&[IndexDef::new("by_shop", &["shop"])]) declares a collection without schemas — list the static among the app's components like a marker — and the context's get, set, delete, scan and range work on Value keys and rows addressed by CollectionRef::local("orders"). Host enforcement — schemas, references, access rules — is the same whichever layer you use.
